# Interview Coach

## What This Is

Interview Coach 是一个本地 Electron + FastAPI + Vue 3 面试训练工具，面向准备 Agent / AI 平台岗位的候选人。产品支持语音模拟面试、独立面试问答、知识库检索、情报导入、简历上下文和面试复盘。

当前工作重点是提升模拟面试和独立面试问答的响应速度，尤其是从提交问题到完整回答结束的等待体验，同时保留现有回答质量和 SSE 流式反馈。

## Core Value

让候选人在真实面试节奏下快速得到可靠、可继续追问的技术面试响应。

## Requirements

### Validated

- ✓ 模拟面试支持 SSE 增量回答、上下文会话和语音朗读 — 现有版本
- ✓ 独立面试问答页面支持问题、追问、历史、知识库检索和来源展示 — 现有工作区改动
- ✓ LLM 支持 Anthropic / OpenAI 兼容通路和备用提供商切换 — 现有版本

### Active

- [ ] 模拟面试和独立问答的完整回答耗时可测量、可比较
- [ ] 面试官回答在不明显降低质量的前提下更快完成
- [ ] 首字流式反馈持续实时，且前端不会因高频增量更新产生卡顿
- [ ] LLM 超时、失败和备用提供商切换有界，不让面试长时间无反馈
- [ ] TTS 不阻塞下一轮面试交互，并保留首句尽早播放能力
- [ ] 复盘等长文本任务保持独立的质量和超时策略

### Out of Scope

- 更换或训练新的基础模型 — 本阶段优先优化现有模型和链路
- 重写知识库检索算法或引入向量数据库 — 当前检索基准不是主要瓶颈
- 重做前端框架或整体视觉设计 — 只做流式渲染和状态反馈所需的局部改造
- 修改已有 SSE 事件协议 — 避免破坏 Electron、浏览器和现有前端兼容性

## Context

当前工作区没有既有 `.planning` 目录，因此本次为 brownfield 项目补建 GSD 上下文。现有代码已经实现独立问答页面，工作区还有未提交改动，不能回滚或覆盖。

代码级基准显示：知识库约 395 条条目，冷加载约 32ms，缓存后约 0.2–0.5ms，单次检索约 0.6–0.8ms。因此优化优先级应放在 LLM 首次响应 / 完整生成、fallback 等待、前端增量渲染和 TTS 交互，而不是先改检索。

## Constraints

- **兼容性**: 保持本地 Electron 和浏览器模式都可用 — Electron 后端是独立进程，前端无构建步骤
- **质量**: 默认不更换模型、不直接关闭所有推理 — 模拟面试、独立问答、复盘需要不同的回答深度
- **协议**: 保持现有 SSE 事件 `d` / `done` / `err` — 已有前端依赖该协议
- **可观测性**: 性能优化必须能区分首字、完整回答、fallback 和 TTS 耗时 — 否则无法判断是否真的变快

## Key Decisions

| Decision | Rationale | Outcome |
|----------|-----------|---------|
| 同时优化模拟面试和独立问答，模拟面试优先 | 两条链路共享 LLM / SSE / 前端能力，但真实面试节奏更敏感 | — Pending |
| 优先优化链路和参数，不更换模型 | 降低响应时间的同时保持现有回答风格和质量 | — Pending |
| 以缩短完整回答时间为主，首字反馈作为辅助指标 | 用户选择的是完整回答优先，但不应牺牲流式感知 | — Pending |
| 复盘使用独立的长文本策略 | 复盘质量不能被短答优化误伤 | — Pending |
