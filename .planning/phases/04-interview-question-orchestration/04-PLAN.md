# Phase 4: 一面题型编排与场景题优先 — Plan

**Created:** 2026-09-07
**Status:** Complete

## Goal

让一面更接近真实大厂技术初筛：先概念，再陌生场景，再有限且轮换的项目深挖，最后概念连环、第二道场景、手撕和反问收尾。

## Tasks

### 1. Prompt orchestration
- 调整一面流程为 19 个面试官回合并建立题型硬约束。
- 把项目贴合规则限制到项目题；概念题独立考机制，场景题引入新约束。
- 增加项目延后与轮换提示，并处理计划回合之后的安全收束。

### 2. Retrieval alignment
- 让动态尾块按题型过滤题库素材。
- 保持二面和旧调用不限制类别；空类别明确表示不注入素材。
- 删除全局“所有题目都改写成简历项目”规则。

### 3. Regression verification
- 增加一面阶段、场景窗口、项目轮换、回合边界和检索过滤测试。
- 运行 compileall、unittest、Node syntax check、diff check、打包后端健康检查和 Electron Windows 打包。

## Acceptance

- 一面前两道正式题为概念题。
- 第 4—6、14—16 回合为两段场景题窗口。
- 项目在第 7 回合才开始且多项目轮换。
- 第 17—18 回合手撕，第 19 回合反问；超出计划仍不抛异常。
- 流式与非流式面试共用提示构造路径，既有 SSE 协议不变。
