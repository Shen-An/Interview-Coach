# Wiki 质量升级计划

## 目标

把当前“情报查看页”升级为可解释、可检索的 Wiki 浏览入口，同时修复 P0 文案/日期问题，并对编译输出做不破坏原文的轻量清洗。保持现有统一检索行为与高命中率不变。

## 固定决策

- 严格按 P0 → P1 → P2 实施，每一阶段先测试再进入下一阶段。
- P0 只修改前端统计口径与本地日期判断，日期逻辑抽成无副作用工具便于测试。
- P1 增加只读 `GET /api/kb/items`，复用 `retrieval.load()` 的统一条目形状；前端使用 API 做概览、搜索、类型/层次/公司/时间筛选。
- P1 条目保留 `source`、`source_urls`、`day`、`space`、`kind`、`layer`、`company`、`freq`、`page` 等溯源字段；不把人格卡、评分细则混入检索素材。
- P2 只清洗 compiled/rendered 输出，不回写 `kb/raw`，并避免修改 URL、代码、原始事实。
- 无构建步骤，前端继续使用现有本地 CDN/vendor 资源。

## 实施任务

### P0
1. 修正“总字数 / 全部喂给面试官”不准确文案。
2. 将知识库过期判断从 UTC 日期改为浏览器本地日期。
3. 为纯前端日期工具添加 Node 测试，并运行现有 Python 测试。

### P1
4. 增加后端条目只读 API 与稳定的概览统计。
5. 增加前端条目列表、搜索与筛选、条目来源/日期展示。
6. 增加 API 和过滤逻辑测试，确认原有刷新、导入、最新情报功能保持不变。

### P2
7. 增加编译/渲染阶段 normalize，覆盖数字范围、标点、括号与空字段保护。
8. 增加 normalize 单元测试，运行评测与全量测试。
9. 同步 README 与 GSD 状态记录。

## 验收标准

- `python -m pytest -q` 全部通过。
- `node --test tests/test_kb_ui_utils.js` 通过。
- `python evals/run.py` 命中率不低于已有 98.2% 基线，且无整库注入回归。
- API 返回可分页/过滤使用的条目元数据，原文链接不丢失。
- `kb/raw` 内容和文件时间不因 normalize 改写。
- 不修改无关 PPT/脚本文件。
