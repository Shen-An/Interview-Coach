## 新场景设计题素材

### 素材 A：企业桌面办公 Agent（对标豆包工作 / WorkBuddy / 千问办公）
- **业务背景**：为 IM（飞书/钉钉）打通的桌面端 AI 办公助手，支持"手机下指令、电脑执行"，上架标准化技能与连接器组成协作小队。
- **量级数字**：行业桌面办公智能体访问量 6 个月内 2000 万 → 6000 万次；单客户 2 万员工；技能/连接器 200+；日均任务 50 万次，其中长任务（>5 分钟）占 8%。
- **考察点**：①多 Agent 编排（谁当 Planner、冲突谁仲裁、为什么要中心化编排）②200+ 技能的路由与检索（大 tool 集治理：分层 Tool→Skill、二级检索、按部门裁剪）③企业上下文感知与权限隔离（文档 ACL 穿透到检索层）④跨端状态同步与断点续跑（checkpoint / 幂等 key）⑤HITL 审批点放在哪一步 ⑥失败降级（技能不可用 → 换连接器 / 转人工）。

### 素材 B：内部 Coding Agent 成本路由网关（AgentSky 式）
- **业务背景**：公司要建一个 Agent 网关，把同一编码任务并行/择优路由到多个 harness × 模型组合，向业务线按预算计费。
- **量级数字**：同任务成本 150 美元 vs 2 美元（75×）；月任务量 10 万条；月预算 30 万美元；要求 P95 端到端 < 8 分钟。
- **考察点**：①评估口径设计（每百万 Token 解决任务数、任务完成率、人工复核成本、返工率）②任务难度预测 → 分级路由（先便宜后升级 vs 直接上贵模型）③影子流量 / A-B 与离线回归集 ④Prompt Caching 与上下文复用降本 ⑤重试成本上限与熔断（避免"重试烧钱"）⑥多模型输出格式不一致的统一约束层。

### 素材 C：Agent 进入研发全链路（得物 Harness 实践）
- **业务背景**：Agent 不只写代码，还要承接需求拆解 → 编码 → 单测 → CI → 灰度发布的全链路。
- **量级数字**：单仓 500 万行代码；日均 PR 800 个；CI 单次 25 分钟；要求 Agent 提交的 PR 一次通过率 > 70%，线上回滚率 < 1%。
- **考察点**：①Harness 五要素落地（固定镜像/标准 IO/自动打分/日志采集/成本统计）②"过程可验证"如何工程化（trace 回放、每步 observation 校验）③回归用例 + 对抗性用例集怎么构造 ④Agent 变更的灰度与自动回滚 ⑤时长/Token 双预算控制 ⑥效果量化指标：需求交付周期、返工率、人工 review 耗时。

### 素材 D：消费级 Agent 的安全合规（Meta HATCH + OpenAI 被调查背景）
- **业务背景**：C 端 AI 助手接入用户邮箱、日历、浏览器与支付，可代替用户执行写操作。
- **量级数字**：DAU 500 万；日均工具调用 3000 万次，写操作占 12%；要求高危误操作率 < 0.01%，可回放率 100%。
- **考察点**：①沙箱隔离与逃逸防御分层 ②工具返回内容视为不可信输入（prompt injection 防线）③写操作二次确认、额度与冷静期 ④零信任授权（MCP + OAuth 2.0 细粒度 scope、可撤销）⑤审计日志与事故回放 ⑥合规指标对齐（信通院 >95%/>90%/>99% 与 Preparedness 分级如何映射到内部 SLO）。

### 素材 E：可被集成的 Agent 基础设施（Codex as a platform 式）
- **业务背景**：把公司自研 Agent 能力开放给外部开发者，提供执行引擎 + SDK + app-server 三层。
- **量级数字**：接入方 2600+；峰值并发会话 5 万；单会话平均 30 步工具调用；需支持多租户额度与计费。
- **考察点**：①三层职责边界与 API 设计（谁管上下文压缩、谁管工具注册）②多租户隔离与配额（会话级/租户级熔断）③"仅调整 Harness 的推理保留与上下文压缩就能让分数从 13.3%→38.3%"——上下文工程为何是杠杆点，你会暴露哪些可调旋钮 ④插件生态的安全审核与沙箱 ⑤可观测性（trace、成本、失败归因）对外开放到什么粒度。
