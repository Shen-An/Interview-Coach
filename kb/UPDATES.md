**新增面试题**
- 多工具连续调用时，如何保证调用顺序正确、输出合规、多个工具的结果不串？ —— 网易/美团｜必考｜调用前校验入参、调用后校验返回，双向 JSON Schema 卡住格式；用状态机校验每步前置条件是否满足；结果按 tool_call_id 绑定回对应调用，避免串号；同一工具连续失败 N 次触发熔断并降级。
- 向量库的分片策略怎么设计，海量文档下召回效果和性能如何优化？ —— 网易/美团｜高频｜按业务域、时间冷热、Embedding 版本三个维度分片；检索链路用 IVF 粗排加 HNSW 精排，配 PQ 量化压内存；叠加元数据过滤缩小候选集，热点 query 结果做缓存。
- HNSW、IVF、PQ、Flat 这几种向量索引怎么选，各自的适用边界是什么？ —— 网易/美团｜高频｜百万级以内追求高精度选 HNSW，代价是内存占用大；千万级选 IVF；亿级且内存受限用 IVF-PQ，接受一定精度损失；十万级以内需要精确检索直接用 Flat 暴力搜。
- ReAct 循环具体怎么实现，每一步的输入输出格式如何约定，循环什么时候终止？ —— 字节豆包 Seed｜必考｜输入是 System 提示加工具 Schema 加历史轨迹；输出先 Thought 再给结构化 tool_calls，执行后回灌 Observation；终止条件三类，任务完成、达到最大步数、出错退出。
- LLM 返回的 tool call 格式不合法或参数错误时怎么容错？ —— 字节豆包 Seed｜必考｜三层兜底：先宽松解析，解析失败让模型重新生成；再用 Pydantic 做参数校验，失败时把明确报错信息回传给模型；工具执行失败则把错误回灌，让模型重试、换工具或降级。
- 多个 Agent 之间怎么通信，子 Agent 挂掉或超时怎么兜底？ —— 字节豆包 Seed｜高频｜通信方式有共享 State 黑板、消息队列、直接函数调用三种；每个子 Agent 配独立超时与预算，超时返回部分结果，由父 Agent 决策重试、换 Agent、降级还是转人工介入。
- 多轮对话中如何保证 Agent 不忘记用户的核心意图？ —— 字节豆包 Seed｜高频｜在 State 里显式维护 core_intent 字段，每轮做意图漂移校验；定期用 LLM 做摘要压缩但保留目标描述；每轮输出目标完成度打分，偏离时主动纠回。
- Agent 的成本怎么控制，效果评测指标体系怎么搭？ —— 字节豆包 Seed｜高频｜成本侧做 Prompt 压缩、模型路由分级、工具调用批处理、单 session token 上限；指标侧看任务完成率、幻觉率、工具调用准确率、P99 延迟、cost per task。
- Agent 的长短期记忆分别怎么实现，摘要压缩在什么条件下触发？ —— 字节豆包 Seed｜高频｜短期记忆靠上下文窗口加 State，长期记忆用向量库存用户偏好与事实、用数据库存结构化规则；压缩触发条件是接近窗口上限、对话轮数超阈值、新会话开始时做归档。
- LangGraph 里三个子图之间怎么传数据，为什么不直接写成一条 Pipeline？ —— 小红书｜高频｜每个节点接收并返回完整 State，靠条件边做路由；拆子图换来的是可单独测试、可复用、可扩展和错误隔离，单条 Pipeline 做不到局部失败不扩散。
- Skills 的知识进化闭环怎么搭，为什么不把这些知识直接写进 Prompt？ —— 小红书｜高频｜闭环是采集用户修正、抽成技能模板、入向量库、检索时按需注入、根据反馈迭代；Prompt 硬编码会持续膨胀且难维护，Skills 实现知识与提示解耦、按需注入、可观测可回滚。
- 高并发场景下 Agent 会话怎么设计，怎么保证会话之间互不干扰？ —— 腾讯｜高频｜每会话独立 State，用 asyncio 或线程池做执行隔离；每会话设 token、工具调用次数、时长三类配额；State 落 Redis 持久化，支持断线后恢复。
- MySQL 的 MVCC 怎么做到读写不阻塞，InnoDB 的行锁什么时候会退化成表锁？ —— 腾讯｜高频｜MVCC 靠 undo log 加 read view 构造一致性快照，读不加锁所以读写互不阻塞；InnoDB 的行锁是加在索引记录上的，条件字段没有索引走全表扫描时锁范围扩大，效果等同表锁。
- 线上服务 OOM 和 CPU 占用飙高分别怎么定位，线程池参数怎么定？ —— 腾讯｜高频｜OOM 先 dump heap，再用 MAT 找大对象和引用链定位泄漏点；CPU 高用 top 定位到进程和线程，转十六进制后 jstack 抓热点线程栈；线程池按任务是 CPU 密集还是 IO 密集定核心与最大线程数，并明确队列容量和拒绝策略。
- 你对自己做的 Agent 做过哪些优化，效果怎么量化？ —— 阿里｜高频｜先用 trace 把耗时拆开，看 TTFT、TBT、工具耗时、排队、上下文组装各占多少；再针对性做模型路由与缓存、并行批处理与超时降级、扩并发削峰；最后给出 P50/P95/P99 与 cost per task 的优化前后数字。
- Opus 5 的 Auto Mode 被以 60% 到 80% 成功率打出 RCE，攻击链是什么，你会怎么防？ —— Embrace The Red｜必考｜攻击链是诱导 WebFetch 改用 curl 下载 ZIP，解压后利用 Python 模块 shadowing，恶意 struct.py 在 import 时被执行；防御是高危操作不进自动批准白名单、用一次性沙箱、限制工作目录白名单、PreToolUse 钩子做风险评分、留审计与快照可回滚。

- Harness 的可重复环境 / 自动打分 / 日志采集三件套，你项目里哪一块最缺，怎么补？ —— 得物｜偶尔｜通常最缺自动打分：需要固定镜像与标准 IO 保证可复现，再用测试通过、静态检查、diff 规模等组合评分，并把 trace 与成本一起采集。
- Agent 改的代码怎么灰度和回滚？ —— 得物｜偶尔｜变更走独立分支与标记，先影子环境与小流量灰度，绑定回归用例与关键指标看板，触发阈值自动回滚，并保留改动归因到具体 Agent 运行 ID。
- Agent 沙箱逃逸的四层防御你怎么搭？ —— OpenAI｜偶尔｜进程/容器隔离与只读文件系统、网络出口白名单、工具能力最小化与参数校验、运行时行为监控与熔断；再加工具返回内容视为不可信输入的注入防线。
- 中美双轨合规：信通院可信要求（简单任务>95%、复杂>90%、接口>99%）与 OpenAI Preparedness Framework 分级，你的系统怎么同时满足？ —— OpenAI｜偶尔｜把外部要求映射成内部 SLO：按任务复杂度分层统计成功率与接口可用率，同时按能力风险分级设置发布门禁与人审要求，用同一套评测与审计管线出双份报告。
- 出了 Agent 失控事故，你的审计与回放链路能还原到哪一步？ —— OpenAI｜偶尔｜需要记录完整 trace：输入、每步计划、工具入参出参、模型版本与 prompt 快照、环境镜像与时间戳，做到按运行 ID 逐步重放并定位失败步。
- 如果线上要接一个来源不明的新模型（如 OpenRouter 上匿名冲榜的 Ox Alpha），你的灰度与评测流程是什么？ —— 来源未标｜偶尔｜先离线回归集与安全红队评测，再影子流量对比，然后小比例灰度并监控完成率、成本、越权与注入指标；全程可一键切回旧模型并隔离敏感数据。｜见于 OpenRouter
- 模型网关（如 OpenRouter）在你的 Agent 架构里承担哪些治理职责？ —— 来源未标｜偶尔｜统一鉴权与配额、模型路由与降级、成本与用量核算、输出格式与安全过滤的统一约束层，以及可观测性埋点，避免业务代码耦合具体供应商。｜见于 OpenRouter
- 「仅调整 Harness 的推理保留与上下文压缩策略就能让分数从 13.3% 提到 38.3%」，为什么上下文工程是杠杆点，你会对外暴露哪些可调旋钮？ —— OpenAI｜偶尔｜因为模型能力被上下文组织方式约束，保留推理痕迹与关键证据能显著改善多步任务；可暴露的旋钮包括历史保留策略、压缩阈值、工具结果截断长度、检索条数与重试预算。

**新场景设计题素材**
- 企业桌面办公 Agent（对标豆包工作 / WorkBuddy / 千问办公）（背景：为与飞书、钉钉等 IM 打通的桌面端 AI 办公助手，支持手机下指令、电脑执行任务，上架标准化技能与连接器组成协作小队，覆盖文档、审批与跨端操作。；量级：行业桌面办公智能体访问量 6 个月内 2000 万到 6000 万次；单客户 2 万员工；技能与连接器 200+；日均任务 50 万次，长任务（超过 5 分钟）占 8%。；考察：多 Agent 编排与仲裁；200+ 技能的分层路由与二级检索；企业上下文感知与文档 ACL 穿透到检索层；跨端状态同步与断点续跑（checkpoint、幂等 key）；HITL 审批点位置；技能不可用时的降级与转人工。）
- 内部 Coding Agent 成本路由网关（AgentSky 式）（背景：公司自建 Agent 网关，把同一编码任务并行或择优路由到多个 harness 与模型组合，向各业务线按预算计费并输出选型报表。；量级：同任务成本 150 美元对 2 美元（75 倍差）；月任务量 10 万条；月预算 30 万美元；要求 P95 端到端小于 8 分钟。；考察：评估口径设计（每百万 Token 解决任务数、完成率、人工复核成本、返工率）；任务难度预测与分级路由；影子流量、A/B 与离线回归集；Prompt Caching 与上下文复用降本；重试成本上限与熔断；多模型输出格式统一约束层。）
- Agent 进入研发全链路（得物 Harness 实践）（背景：Agent 不只写代码，还要承接需求拆解、编码、单测、CI 到灰度发布的研发全链路，进入研发飞轮需要需求清晰、过程可验证、效果可量化。；量级：单仓 500 万行代码；日均 PR 800 个；CI 单次 25 分钟；要求 Agent 提交 PR 一次通过率大于 70%，线上回滚率小于 1%。；考察：Harness 五要素落地（固定镜像、标准 IO、自动打分、日志采集、成本统计）；过程可验证的工程化（trace 回放、每步 observation 校验）；回归与对抗性用例集构造；Agent 变更灰度与自动回滚；时长与 Token 双预算控制；交付周期、返工率、review 耗时等效果指标。）
- 消费级 Agent 的安全合规（Meta HATCH 与 OpenAI 被调查背景）（背景：C 端 AI 助手接入用户邮箱、日历、浏览器与支付，可代替用户执行写操作，面临沙箱逃逸、提示注入与监管调查风险。；量级：DAU 500 万；日均工具调用 3000 万次，写操作占 12%；要求高危误操作率低于 0.01%，可回放率 100%。；考察：沙箱隔离与逃逸分层防御；工具返回内容视为不可信输入的注入防线；写操作二次确认、额度与冷静期；零信任授权（MCP 与 OAuth 2.0 细粒度可撤销 scope）；审计日志与事故回放；外部合规要求映射到内部 SLO。）
- 可被集成的 Agent 基础设施（Codex as a platform 式）（背景：把公司自研 Agent 能力开放给外部开发者，提供执行引擎、SDK 与 app-server 三层，支持第三方插件接入自有系统。；量级：接入方 2600+；峰值并发会话 5 万；单会话平均 30 步工具调用；需支持多租户额度与计费。；考察：三层职责边界与 API 设计（上下文压缩与工具注册归属）；多租户隔离与会话级、租户级配额熔断；上下文工程可调旋钮的暴露范围；插件生态安全审核与沙箱；trace、成本与失败归因的对外可观测粒度。）
